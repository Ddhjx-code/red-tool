# 月宫一夜 · 叙事重构规格（decision-complete）

本规格用于委派改写 `data.js` 的叙事文案。**所有结构性字段不在改写范围内**，只改文字。

## 一、要解决的三个缺陷（诊断已证实）

| 缺陷 | 证据 |
|---|---|
| ① 开局无法认知自己是唐玄宗 | `meta.intro` 不含「你」；`[start]` 用第三人称「玄宗于宫中玩月」；仅 1/12 节点称主角为玄宗，而 7/12 用「你」→ 人称不一致 |
| ② 事件有序列但无因果链 | 罗公远为何提议、你为何想去、为何只能择一事、次夜为何制曲 —— 四处动机全部缺失 |
| ③ 选项无法推理 | 选项 delta 有真实区分（见下），但资源语义从未交代，warmth=0 后果从未说明 |

## 二、因果脊柱（本次改写要建立的）

**动机 = 你素好音律，欲闻月中天乐。** 这一句让整条链通电：

```
素好音律，总觉得宫中所奏少些什么
  → 罗公远提议登桥 = 你有理由答应（不是被动跟随）
    → 桥上折桂御寒 / 目不斜视 = 都为「走到广庭听曲」服务
      → 广庭择一事 = 记曲直接服务于你的目标
        → 归后制曲 = 回报落地（你来拿曲子，现在把它做出来）
```

## 三、资源语义（必须在 intro 交代）

引擎已有机制，但玩家看不见语义。必须写明：

| 资源 | 上限 | 语义 | 后果 |
|---|---|---|---|
| `warmth` 暖意 | 3 | 你身上的暖意。月宫极寒，暖意是你能待多久 | **散尽（<=0）则不能进广寒，此夜作废，强制 `end_weiru`** |
| `tune` 记曲 | 2 | 记下的声调 | **满值 2 → 霓裳羽衣曲可完整重现（最好结局 `end_nichang`）** |
| `dance` 观舞 | 2 | 领会的舞姿神韵 | 满值 2 → 得其意而声调不全（`end_banyue`） |

## 四、`[court]` 的两难必须可读（核心）

当前三个选项 delta 已构成真实取舍，但玩家看不出。改写时**必须在节点文案里把取舍讲明**：

| 选项 | delta | 取舍 |
|---|---|---|
| `[0]` 静立凝神，密记其声调 | `warmth-1 tune+2` | 得**完整**声调；代价是静立不动 → 寒气一层层侵上来 |
| `[1]` 近前细观舞姿 | `tune+1 dance+2`（**暖意不损**） | 得神韵 + 部分声调；走动反而不耗暖意，但声调拾不全 |
| `[2]` 开口问一句：此何曲也 | `warmth-1` | 耗神、寒意趁虚而入，**只得曲名**，声调舞姿都没有 |

关键反差：**想要完整的曲子必须付出暖意**，而看舞不耗暖意却拿不到完整声调。这个反差是游戏的真正赌注，必须让玩家在选之前就能推理。

## 五、史料纪律（硬要求）

现有考据卡已有极高标准，必须延续：

- `knowledge[0]` 已写明「桥上行时可折一枝桂御寒，**此为本作演绎，原文并无此事**」
- 《太平广记》原文里玄宗是**因罗公远提议才去的**，并无「素好音律、欲闻天乐」的预设动机
- **所以本次新增的动机属于本作演绎，必须新增一条考据卡明确标注这是演绎，不得伪装成史实**
- 「玄宗好音律」「创霓裳羽衣曲」本身是公认史实；「此夜他带着求曲的欲望登桥」是本作戏剧化处理 —— 两者必须区分清楚
- 主干仍以《太平广记》罗公远版为准，约束层仍取《龙城录》，此分工不得改变

## 六、人称统一规则

- **主角一律第二人称「你」**，不再出现「玄宗」「明皇」「帝」作叙事主语
- 「陛下」只作为**罗公远对你的称呼**保留（这是对话内的合理用法）
- 素娥、公远等他人一律第三人称

## 七、文风约束

- 保持唐人传奇语气，**不要写成游戏说明书口吻**
- 资源语义的交代要融进叙事，不要出现「规则」「提示」「系统」这类现代词
- `meta.intro` 用 `\n` 分行（`#intro-body` 是 `white-space:pre-line`）
- 文言层与白话层必须**一一对应**：每段文言都要有对应白话

## 八、绝对不得改动的结构字段（引擎与测试依赖）

| 字段 | 约束 |
|---|---|
| 节点 ID | 必须保持 12 个：`start, stay, bridge, lookback, gate, force, court, listen, watch, askname, return, second` |
| `choices[].next` | 接线不得改动 |
| `choices[].warmth/tune/dance` | delta 不得改动（结局判定依赖） |
| choice 数量 | 每节点选项数不变，总计 21 |
| 结局 ID | 恰好 5 个：`end_nichang, end_banyue, end_weiru, end_buyun, end_renjian`。`\bend_[a-z]+\b` 在 data.js + index.html 必须恰好命中这 5 个 |
| `endings[].name` / `endings[].cond` | 可微调措辞但不得改名（结局清单 chip 依赖 name） |

## 九、必须同步改写的配套内容

| 内容 | 数量 | 说明 |
|---|---|---|
| `meta.intro` + `gloss.intro` | 1 | 身份 + 动机 + 资源语义 |
| 节点 `text` + `gloss.nodes[id]` | 12 | 因果链 + 人称统一 |
| `choices[].text` + `choices[].outcome` + `gloss.outcomes["<nodeId>:<index>"]` | 21 | 选项可读 + 后果明示 |
| `endings[].text` + `gloss.endings[id]` | 5 | 回报落地 |
| `ruby` | 现有 14 条 + 按需新增 | **新增术语必须在正文真实出现**，不得留孤儿 |
| `knowledge` | 现有 3 条 + 新增 1 条演绎说明 | 见第五节 |

## 十、验收标准

1. intro 含「你」且明确身份为天子
2. `[start]` 不再以「玄宗」作叙事主语
3. 全文人称统一（主角一律「你」）
4. intro 交代三个资源语义与 warmth 散尽的后果
5. `[court]` 文案能让玩家在选之前推理出取舍
6. 动机链在 start → bridge → gate → court → return → second 全程可见
7. 新增考据卡明确标注动机是演绎
8. 所有结构字段与第八节完全一致
