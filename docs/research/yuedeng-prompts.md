# 月下灯会 · 月亮素材提示词 v1（M-01 主图 + 2 张备选）

> 用途：兑现用户驳回意见「**月亮还是不好看，建议文生图月亮**」。
> CSS 手绘月已被连续否决两次（第一次「太像素化」，第二次「还是不好看」），
> 故月亮改为**文生图位图素材**。本文档给出该素材的**生成期提示词**，
> 由 `tests/gen_yuedeng_moon.py` 逐字读取执行。
> 出图平台：通义万相（`wan2.7-image-pro`，与系列同平台），契约见
> `docs/research/maas-image-api.md`。
> 提示词纪律继承自 `docs/research/yueyan-prompts.md`。

---

## 〇、通用要求（3 张全部适用）

1. **生成尺寸一律 `1024*1024`（星号，不是 `x`）**。网关总像素区间
   **[589,824, 16,777,216]** 为硬限制，超出即 **HTTP 400 InvalidParameter**
   （非静默回落）；`1024*1024` = 1,048,576 px，落在区间内。
   写 `x` 会**静默回落成正方形**，故全脚本只用星号。
2. **强制四步管线**（与月宴 0d-§4.4 同构，但**降采样档换成平滑档**）：

   ```
   生成 1024*1024（纯品红 #FF00FF 底）
     -> 色度键 + 从画面四边向内做区域生长抠图（chroma-key + flood-fill）
     -> 溢色清除（despill）→ halo 清理 → 一圈 alpha 腐蚀（杀掉底色残边）
     -> 裁到月轮不透明包围盒并正方化（紧凑方裁，便于接线）
     -> Pillow **LANCZOS** 降采样到 512 × 512（实际比例由裁切框测得，约 1.6:1）
     -> **无损 WEBP**
   ```

   **降采样是强制步骤，不是可选回退**（网关下限 768²，任何 < 768 的目标尺寸
   都无法直接生成）。
3. **画风钉死到具体画种**：`写实天文月面摄影质感` + `天文望远镜实拍风格`。
   **禁止裸 `国风` 或裸 `Chinese style`**（→ 通用感、不一致）。
   选这一画种的理由：前两次被否的根因是**月面质感不真实**——12 边形
   clip-path（第一次）与径向渐变 + 柔化环形山（第二次）都仍是**平涂块面**，
   读起来是「画的圆」而不是「月亮」。写实天文摄影是**唯一能提供真实月面
   肌理**（环形山、月海、高地明暗起伏）的画种，且它与本作的暖调夜空
   不冲突——月亮本就是夜空里唯一的写实焦点。
   同时它完成**系列区隔**：对月宴的 `工笔线描 + 宋代笺纸小品画`（平涂暖纸），
   对月宫的 `绢本设色 + 青绿山水`（冷蓝仙境）。
4. **色板 hex 必须写进提示词**（不得自行调色）。本素材的**自有闭板恰好三个
   token**，别无其他：

   | token | hex | 用途 |
   | --- | --- | --- |
   | 月白 `--moon` | `#F2E4C4` | 月轮基色（暖米白） |
   | 月面暗部 `--moon-dk` | `#C8B795` | 月海 / 环形山暗部 / limb 过渡 |
   | 月缘墨褐 `--moon-rim` | `#3A2E26` | 月缘（limb）暗化 |

   第 4 个 hex **桂金 `--halo` `#E8B84B`** 属于**画面外的夜空辉光**，
   **必须写进正文但必须被显式排除**（见下「为什么桂金 hex 不进后缀」）。
5. **单一暖锚点纪律**：月白 `#F2E4C4` 是全图唯一的暖锚点，暖色不得四处溢出。
6. **提示词正文 50–200 字**，「使用具体的描述替代抽象概念」。
7. **背景必须问出品红底**：素材要透明背景合成到 CSS 夜空上，故后缀内含
   `背景为纯品红#FF00FF纯色平涂`——品红与本板三色距离均 > 218，
   是唯一不会误伤月面的键色。

### 固定风格后缀（3 张必须逐字节相同，直接复制）

```
写实天文月面摄影质感，天文望远镜实拍风格，月面肌理柔和细腻明暗过渡自然，整体暖米白调，色板严格限定为月白#F2E4C4、月面暗部#C8B795、月缘墨褐#3A2E26，不得引入板外色，不偏冷蓝不偏银白不发青，画面绝无光晕光斑辉光星点云层，背景为纯品红#FF00FF纯色平涂，月轮边缘干净利落便于抠图，不用文字，不用水印，高清。
```

> ⚠️ **一致性杠杆最高的一项就是这个后缀。3 张之间不得有任何改动（含标点与空格）。**
> `tests/gen_yuedeng_moon.py` 在发任何请求之前**断言其逐字节相同**，
> 断言方式与 `tests/gen_yueyan_assets.py:350-361` 同构（取每张提示词的
> **最后一行**构成集合，集合必须恰好只有该后缀一个元素，且与该常量
> **逐字节相等**），不一致即 `FATAL` 退出、一张都不发。

### 为什么桂金 hex 不进后缀（唯一的有意例外）

后缀注入 **3 个** hex，`桂金#E8B84B` **不在其中**。理由与月宴朱砂的处理同构：

| 事实 | 后果 |
| --- | --- |
| 辉光**必须留在 CSS**（五档月相的 halo opacity 从 P1 `0.58` 到 P5 `0.14` 逐档变化，烘焙进静态位图就无法随档变化） | 若后缀含桂金 hex，等于**授权模型画辉光**，与「不得烘焙辉光」直接矛盾 |
| `style.css` 的 `.m-halo` 径向渐变已承担辉光，且刚被柔化过 | 素材自带辉光会与 CSS 辉光**叠加成双层光晕**，正是被否的那类「不好看」 |

故桂金 hex **只写进 3 张正文的排除句**（`夜空辉光桂金#E8B84B 由画面外叠加，
本图绝不含任何辉光`）。这不是漏注入：「色板 hex 必须写进提示词」在 3/3 张上
成立（后缀 3 个 hex 全员注入），第 4 个 hex 在全部 3 张的正文里以**排除句**
形式注入。**这是把「四 token 闭板」与「辉光不得烘焙」两条同时满足的唯一写法。**

### 禁用词（3 张全部适用）

| 类别 | 禁用 |
| --- | --- |
| 质量套话堆叠 | `8K` `ultra HD` `highly detailed` `masterpiece` `best quality` `trending on artstation` `award-winning`（**最多留一个 `高清`**，已在后缀内） |
| 无指涉形容词 | `beautiful` `amazing` `stunning` `epic` `cinematic`（单独使用） |
| 空泛文化词 | 裸 `国风` / 裸 `Chinese style` |
| 裸冷词 | `冷色调` / `蓝色调` / `银白色` / `青色` / `blue tone`（**月亮是最容易漂成冷白的主体**） |
| 渐变与厚涂 | `渐变高光` `塑料厚涂` `粗黑卡通描边` `卡通` `插画`（→ 退回被否过的平涂块面） |
| **像素化** | `像素画`（**用户第一次驳回的直接根因，必须进负向词**） |

### 禁用符号（10 项）→ 进 `negative_prompt`

```
玉兔，嫦娥，月宫，广寒宫，桂树，星空，星星，云层，云朵，光晕，辉光，光斑，镜头光晕
```

这些项**不可像素化测量**（画面里有没有「嫦娥」无法用色值判定），
故**提示词层排除是唯一防线**：全部进 `negative_prompt`，并在本文档逐张记录。

**⚠️ 桂树 / 月宫 / 玉兔 三项是与月宫（yuegong）区隔的关键**：月宫的月轮内有
桂树淡影与月宫语义，本作月面**只有真实月面肌理，不含任何剪影**。
正文已显式写「不含任何建筑人物动物剪影与桂树月宫」，负向词再兜一遍。

### 冷色纪律（月亮专项）

月亮是全系列**最容易漂成冷蓝银白**的主体。故：
- 负向词固定含 `冷色调，蓝色调，银白色，青色，blue tone`；
- 后缀内再写一遍 `不偏冷蓝不偏银白不发青`；
- **脚本客观复核**：对不透明像素算平均 RGB，要求 `mean_R > mean_B`
  （暖调判据）。这一条**可程序化测量**，不依赖目视。

## 三、月相裁决：**一张素材，不做五张**（必须读）

游戏有五档月相（P1 满月无云 → P5 薄云遮月），由 `data-phase` 属性 +
`--cover` 自定义属性驱动，`MOON_COVER = {P1 0.00, P2 0.18, P3 0.35,
P4 0.55, P5 0.75}` 设定云带高度（`data.js:85`）。

**裁决：只生成一张干净满月月轮，云层继续由既有 CSS 叠加。** 理由四条：

| # | 理由 | 依据 |
| --- | --- | --- |
| 1 | **云量必须逐档精确，扩散模型做不到**。云带高度由 `--cover` 精确驱动（0.00 / 0.18 / 0.35 / 0.55 / 0.75），文生图无法保证「云遮 18%」——五张素材的云高会各自漂，与 `MOON_COVER` 对不上，反而**破坏既有月相契约** | `data.js:71-85`、`style.css:524` |
| 2 | **辉光已经证明「必须留在 CSS」**。`.m-halo` 的 opacity 从 P1 `0.58` 逐档降到 P5 `0.14`，烘焙进位图就无法随档变化。**同一条逻辑对云层完全成立**：云带高度也是逐档变量，故云层同样必须留在 CSS | `style.css:548-558` |
| 3 | **既有云带与流云刚被柔化过且能用**。`.m-band`（底实顶柔）+ 三条 `.m-wisp`（逐档 opacity）已实现「五档可区分」，§4.3 只要求「月相可区分」，不要求「云也是位图」 | `style.css:519-568`、spec §4.3 |
| 4 | **一张素材 = 接线面最小**。接线 agent 只需替换 `.m-disc` 的绘制方式，`.m-halo` / `.m-rim` / `.m-clouds` / `.m-band` / `.m-wisp` **一行都不用改**，五档月相契约原样保留 | `style.css:453-568` |

### 接线契约（给接线 agent 的确切预期）

- **素材内容 = 只有月轮本体**：无辉光、无光晕、无星点、无云层、无剪影。
- **素材是月轮不透明包围盒的紧凑方裁**：月轮**充满整张 512 × 512 画布**，
  四角透明（月轮内接于方画布）。故接线时
  **`<img>` 的 width/height 直接等于期望的月轮直径**——
  例如 `.m-disc` 现为 198 px，则 `width:198px; height:198px` 即得 198 px 月轮，
  不需要再按「素材里月轮占 80%」换算。
- **`.m-halo` / `.m-rim` / `.m-clouds` / `.m-band` / `.m-wisp` 全部保持 CSS 不动**，
  它们叠在这张 `<img>` 之上/之下即可。
- **透明背景**：素材自带 alpha 通道，直接合成到 `.stage` 的三层夜空上。
- **`view-result` 的 `.lamp-stage .moon { transform: scale(0.36) }`** 依旧生效——
  512 px 素材缩到 ≈ 82 px 显示仍有 6.2× 像素余量，不会糊。

## 四、验收口径（客观指标 + 一次人工目视）

**⚠️ 本环境任何 agent 都没有视觉能力**（实测报错
`Cannot read image (this model does not support image input)`），
故**「月亮好不好看」只能由用户判定**。脚本只做**客观、可程序化**的检查，
**绝不**产出任何视觉评价。

### 脚本自动做的（客观）

| # | 检查项 | 判据 |
| --- | --- | --- |
| 1 | 后缀逐字节相同 | 发请求**前**断言，不一致即 `FATAL` 退出 |
| 2 | 请求尺寸合规 | `parameters.size` 用**星号**且总像素 ≥ 589,824 |
| 3 | 入库尺寸合规 | 一律 512 × 512（= 228 px 显示位的 2.245×，> retina 所需的 456 px） |
| 4 | 入库尺寸 ≥ 显示位的 2× | 512 ≥ 2 × 228 = 456 ✅ |
| 5 | **透明背景** | 四角 alpha **必须 = 0**；画布中心 alpha **必须 = 255** |
| 6 | **无烘焙辉光** | 不透明像素包围盒不得贴到画布边缘（贴边 = 辉光被烘焙进去了） |
| 7 | **非像素化** | 不透明像素的**不同色值数**必须 ≥ 1500（量化像素画只有 ≤ 24 色）；且脚本**不含任何 BOX / NEAREST / 量化** 代码路径 |
| 8 | **暖调不漂冷** | 不透明像素平均 `R > B` |
| 9 | 色板归属 | 最近 4 色归属（月白 / 月面暗部 / 月缘墨褐 / 桂金），份额恰加和 100%；**桂金份额必须 ≈ 0**（辉光未被烘焙） |
| 10 | 格式 | 一律 `.webp` **无损**；不产出 `.png` 入库文件 |

### 人工目视做的（一次过，由用户判定）

| # | 检查项 | 判据 | 不合格的后果 |
| --- | --- | --- | --- |
| 1 | **月亮好不好看** | 用户主观判定 | 换 M-02 / M-03，或收紧后缀重出 |
| 2 | 是否暖、不偏冷蓝银白 | 与 CSS 夜空协调 | 重出（收紧冷色禁令） |
| 3 | 是否出现辉光 / 星点 / 云 | 三项均不出现 | 重出（收紧后缀排除句） |
| 4 | 是否出现桂树 / 月宫 / 玉兔剪影 | 均不出现 | 重出（与 yuegong 撞车） |
| 5 | 是否有 AI slop 感 | 无塑料光泽、无渐变高光、无粗黑卡通边 | 收紧后缀禁用句 |

**三选一的方式**：

```bash

# 2) 只出主图
python tests/gen_yuedeng_moon.py --only M-01

# 3) 强制重出（忽略续跑跳过，且重新调网关）
```

## 五、出图后交付

- **入库路径**：`tools/yuedeng/assets/img/moon.webp`（主图）、
  `moon-b.webp` / `moon-c.webp`（备选）。包内相对路径引用，**不得出现任何外链**。
- **中间产物**：1024 × 1024 原始 PNG 落在 `docs/research/yuedeng-drafts/raw/`，
  **不进包**。**它是断点续跑的缓存**：已存在即不再调网关，故脚本的
  后处理阶段是**逐字节可复现**的。
- **不得出现 `.png` 素材**：`find tools/yuedeng -name "*.png"` 命中数必须为 **0**。
- **OSS URL 约 24h 过期**，故脚本在拿到 URL 的**同一次运行内立即下载**，
  绝不只存 URL。

### 关于「可复现性」的诚实说明

脚本逻辑**零随机**（无 seed、无 shuffle、无随机分支），全部后处理是
numpy 确定性运算。**但出图模型本身是非确定的**——同一提示词两次调用会返回
两张不同的图。这一点**无法消除**，本脚本的处理方式是：

1. 原始 PNG 缓存在 `docs/research/yuedeng-drafts/raw/`，**已存在即复用**，
   故重复运行 `python tests/gen_yuedeng_moon.py` **不会**重新调网关、
   **不会**换图，入库素材逐字节稳定；
2. 只有显式 `--force` 才会重新调网关并接受一张新图；
3. 配额失败**重试到预算耗尽后大声报错**，绝不静默跳过。

### 给接线 agent 的实测事实（不含任何视觉评价）

1. **辉光份额 0.00%（三张皆是）** → 客观证明**辉光没有被烘焙进素材**，
   `.m-halo` 的逐档 opacity（P1 0.58 → P5 0.14）可以照常工作。
2. **四角 alpha 全 0、中心 alpha 255** → 透明背景成立，可直接合成到 CSS 夜空。
3. **轮廓圆度 1.005–1.010**（不透明面积 / 同半径内接圆面积）→ 月轮轮廓
   **接近完美正圆**，不是椭圆也不是多边。
4. **不同色值数 16,404–25,227** → 客观证明**素材不是像素画**
   （量化像素画只有 ≤ 24 色）。全脚本只有**一处** `.resize()`，且是 `LANCZOS`。
5. **三张的平均亮度都低于旧 CSS 月面**。旧 `.m-disc` 的基色是
   `--moon #F2E4C4`（亮度 ≈ 228），而三张素材的不透明像素平均亮度为
   **176.5 / 187.4 / 177.2**。接线后月轮会比原 CSS 版**偏暗一档**。
   若需拉回原亮度，接线 agent 可在 `<img>` 上加 `filter: brightness(1.15)`
   之类的 CSS 调整——**这属于接线阶段的工作，本脚本不做**。
6. **M-02 最亮且暗部最少**（`moon-rim` 归属仅 4.83%，亮度 p10 = 151）；
   **M-01 / M-03 的暗部更多**（`moon-rim` 归属 13.50% / 14.84%，
   亮度 p10 = 65 / 95，M-01 最暗处亮度低至 3）。
   注意：M-01 含有**比 `--moon-rim #3A2E26` 更暗**的像素（最近色归属把它们
   归到 moon-rim，但精确色值超出闭板的暗端）。M-02 的最亮主色
   `(237,220,187)` 最接近 `--moon #F2E4C4`。
7. **无损 WEBP 体积约为 q95 的 3.2 倍**（实测：M-01 lossless 224,904 B vs
   q95 69,230 B = 31%；q90 47,182 B = 21%；q80 28,104 B = 12%）。
   选择无损的理由见本节末「为什么选无损 WEBP」。若将来体积成为约束，q95 是**唯一**合法降档路径
   （q80 以下会引入可见的渐变带状伪影）。

### 为什么选无损 WEBP（而不是高质量有损）

| 事实 | 后果 |
| --- | --- |
| 月面是**大面积平滑渐变**（实测不同色值数 1.6 万–2.5 万，相邻像素平均 ΔR 仅 2.69–4.92） | 有损 WEBP 的 **ringing + banding** 恰好在这类平滑渐变上最显眼——正是「看起来廉价」的那类伪影 |
| 用户已两次驳回月亮 | 不能在压缩环节再引入一种新的伪影来源 |
| 本作只有**一张**月亮素材（不是月宴的 22 张） | 219 KiB 是**单个素材**的体积，不是 22 张的总和，不构成预算问题 |
| 无损逐字节保真 | 后处理管线（抠图 / 腐蚀 / LANCZOS）的结果**原样入库**，验收指标测的就是真实素材 |

故 `WEBP_LOSSLESS = True`、`quality=100`、`method=6`。
