# 设计知识沉淀（来自 canvas-ui + video-shotcraft）

> 2026-08-13 调研两个开源项目的设计知识，提炼为打铁花互动展册（及系列后续工具）的设计准则。
> 来源：github.com/DavidHDev/canvas-ui（3.8k★，canvas 特效组件库）、github.com/Vincentwei1021/video-shotcraft（4.9k★，电影感动效方法论）。

## 一、动效准则（video-shotcraft aesthetic-rules 转译到互动 H5）

### 节奏
1. **落定必呼吸**：承载信息的元素（标题/展签/关键画面）落定后静止 ≥1s 再动；呼吸感优先给记忆点，不给普通元素。
2. **速度感来自加速度**：一切运动非线性缓动 + 错峰；匀速 = 廉价。群体元素入场「越来越快」+ 末尾 0.5s 静止。
3. **宁慢勿快**：首版默认放慢一档；主体动作弧 ≥3s；时间线预留 hold/rest 预算。历史反馈全部指向「放慢」，没有一次「太慢」。

### 质感与构图
4. **光效宁缺毋滥**：高光/扫光不群发——每屏最多给主角一次；批量元素靠运动本身出彩，不靠逐个发光。
5. **一屏一主角**：每屏一个主角元素 + 一条完整动作弧（起-承-落），多元素并舞撑不起第一印象。
6. **结尾即峰值**：终章是全片能量最高点，元素汇聚、特效拉满；初版收尾几乎总是偏保守，默认加码一档。
7. **文字两态**：要么「要读」（达标的字高+对比度），要么「纹理」（明显虚化让人不读）；不存在「摆了但读不清」的中间态。要读的字幕 ≥ 帧高 5%，辅助文字 ≥3%。

### 流程
8. **交付前自检**：自己先逐帧/逐像素检查，不把首检交给用户（对我们 = 无头截图 + 像素断言）。
9. **一种手法只当一次主角**：5 屏的签名交互必须互不相同，重复即删。
10. **确定性渲染**：禁 Math.random()，一切伪随机固定种子（mulberry32），逐帧可复现、可断言。

## 二、视觉语言准则（video-shotcraft SKILL 核心理念）

11. **视觉语言从题材自身生长**：先定 tokens（字体/字号层级/间距/圆角/色板/材质），全部元素复用这套 tokens，不另造皮肤。打铁花展册 tokens = 焦墨五色 + 金粉（唯一强调色）+ 宣纸白 + 楷体。
12. **电影感来自光影与节奏的配合，不来自炫技**：被反复认可的是「单主角完整动作弧」「物理隐喻的加速度」「riser→impact→sparkle 的节奏句式」。
13. **一屏只讲一个动效**：信息聚焦，删掉一切装饰性动画。

## 三、技术天花板参考（canvas-ui）

14. **Shader 是视觉上限**：专业级火焰/流体/墨晕/粒子都是 WebGL shader 实现（Blaze=火花烟雾热畸变、Liquid=流体、Clouds=雾气、Particle Reveal=粒子聚合成字）。小工具容器允许 WebGL——展册的墨晕转场、金粉铁花可以用 shader 做，这是 Canvas 2D 粒子之上的第二级天花板。
15. **特效叠在真实内容上**：效果层跑在内容之上，内容保持可交互——展册的插画是内容层，粒子/光效是效果层，分层合成。
16. 许可：canvas-ui 为 MIT + Commons Clause，可学习技法、自写实现（离线 zip 也不能 npm 安装）。

## 四、落到打铁花展册的执行清单

- [ ] 每屏写一张「动效配方卡」：阶段（蓄力→冲击→落定→呼吸）+ 时值 + 缓动，全部非线性
- [ ] 首屏标题动作弧 ≥3s；展签落定 hold ≥1s；终章做成能量峰值
- [ ] 5 屏签名交互互不相同（长按/点按/滑动/点按/浮现）
- [ ] 粒子改 mulberry32 种子随机，验证可复现
- [ ] 文字按「要读/纹理」两态审查，展签字高达标
- [ ] 验证脚本加关键帧截图 + 像素断言（标题落定/冲击瞬间/终章峰值）
- [ ] 二期升级项：WebGL 墨晕转场 + 金粉 shader（canvas-ui 技法自实现）
