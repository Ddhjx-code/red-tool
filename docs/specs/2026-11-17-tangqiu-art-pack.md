# 糖球转转 · 美术素材提示词包 v1

> 用途：把《糖球转转》的角色/怪物从「代码画的几何圆形」换成成套的贴纸风美术素材。
> 遵循 `game-art-prompt-pack` 方法论：风格锚点逐字复用、单主体验证后批量、只出单方向、效果不画进图。

## 0. 本版相对 v0（纯代码绘制）的改动

- v0：主角与怪全部用 canvas 路径画（圆 + 三角 + 方块），形体单薄，缩放后边缘糊，被判定「太粗糙」。
- v1：主体改由图片素材承载（`assets/art/*.png`），**光效、受击闪白、血条、粒子、拖尾仍由代码叠加**（规则 9：效果绝不画进图）。
- 保留代码绘制的部分：粒子、光环、飘字、掉落糖、UI。这些是「动效层」，图片化反而做不出动态。

## 1. 风险前置

| 风险 | 本包解法 |
|---|---|
| 六张图风格漂移，摆在一起不像一套 | 风格锚点逐字复制，一个字不改；先跑主角锁参数，再按槽位表批量 |
| 同一个粉色系主体互相串味（主角粉糖球 / 蛋糕卫兵粉色） | 每个主体给**两条互不重复的识别线索**：颜色 + 剪影（主角=圆+星芽；蛋糕=三层塔+草莓） |
| 模型自动加投影/地面，抠图后留脏边 | 负面词把 `shadow, cast shadow, contact shadow, ambient occlusion, ground, floor` 逐字排除 |
| 画的太精致，缩到 64px 糊成一团 | 强制「大色块 + 粗描边 + 五官仅两点」；细节上限：每个主体不超过 3 个装饰元素 |
| 小尺寸下描边太细看不见 | 描边固定为画布宽度的 1.2%（1024 画布约 12px），缩放后仍是实线 |

## 3. 风格锚点（逐字复用，不得改动）

**中文：**

> 圆润贴纸风卡通，2D 竖屏手游单体素材；主体外轮廓是一圈粗细均匀的手绘墨线，颜色为深褐 #4A3A38 而非纯黑；内部为大面积平涂色块，仅加一层同色系浅渐变（上亮下暗）；高光用一到两个纯白小圆点；形体比例偏圆偏矮，Q 版，头身比约 1:1.2；五官只保留两颗黑豆眼和一点腮红，不画嘴巴细节；配色为奶油糖果色，单一主体用色不超过五色；光源统一来自左上 45 度，仅在形体转折处加一层更深的同色阴影。

**English（同一段，逐字复用）：**

> rounded sticker-style cartoon, single 2D mobile game asset, even hand-inked outline in dark warm brown #4A3A38 (not pure black) at constant width; flat color fill with one layer of subtle same-hue gradient (lighter top, darker bottom); one or two pure white dot highlights; chibi proportions, round and short, head-to-body about 1:1.2; face limited to two black bean eyes and a touch of blush, no mouth detail; creamy candy palette, at most five colors per subject; single light source from upper left 45 degrees, one layer of deeper same-hue shadow only at form turns.

**收尾统一句：**

> 纯色奶油白背景 #FFF6F2，无渐变、无投影、无地面、无环境光遮蔽，主体居中，占画面 70%，四周留足空白。

## 7. 批量执行清单

1. 只出 `hero` 一张 → 看风格对不对（描边厚度、色块干净度、可爱度）
2. 出 `pudding` 一张 → 与 hero 并排，检查是否同一套
3. 两张过关 → 锁定参数与完整提示词全文存档
4. 按槽位表出 `jelly` / `bat` / `cake` / `boss`
5. 每张检查：四角是否纯色可抠、主体是否居中、有无投影脏边
6. 统一缩放到 256×256（BOSS 320×320），压成 8 位 PNG

## 8. 命名与归档

- 源图：`docs/art/tangqiu/src/<code>-v1.png`（1024 原图，入库留档）
- 进包：`tools/tangqiu/assets/art/<code>.png`（256 或 320，8 位）
- 代码按 `<code>` 索引，缺图时自动降级到 v0 的几何绘制（见 §11）

## 9. 验收自检清单

- [ ] 六张并排，一眼能看出是同一套（描边色、色温、圆润度一致）
- [ ] 每张只有一条颜色线索 + 一条剪影线索，互不重复
- [ ] 缩放至 64px 仍能分辨种类
- [ ] 无投影、无地面、无渐变背景，边缘干净可抠
- [ ] 主角与蛋糕卫兵（同为粉色系）不混淆
- [ ] BOSS 的华丽感来自层次与王冠，不来自彩光

## 10. 集成约定（给实现用）

- 图片只承载「主体」，光效用代码：受击闪白用 `ctx.globalCompositeOperation = 'lighter'` 叠白圆，不加第二张图
- 阴影用代码画椭圆（`rgba(91,75,75,0.12)`），不画进图
- 加载：`new Image()` + `onload` 计数，全部就绪前先跑 v0 几何绘制，避免白屏
- 缓存：`<meta name="viewport">` 不变；图片走 `./assets/art/xxx.png` 相对路径
- 镜像：敌人朝左时 `ctx.scale(-1, 1)`，不额外出图

## 10.5 v2 增补（七关版，共 22 张）

七关版把「放大杂兵 + 代码补王冠」的偷懒路线砍掉了，七个 BOSS 全部单独出图。

| `pudding` `jelly` `bat` `cake` `gum` `cloud` `choco` `cookie` `cap` `berry` `star` | 十一种杂兵 | 见色板 | 各一条剪影线索 | 200 |
| `b1`–`b4` | 布丁王 / 果冻王 / 巧克力巨人 / 三层蛋糕王 | 各自母色 + 金 | 母体放大 + 内置王冠 | 288 |
| `cloudK` `capK` `starK` | 棉花云王 / 汽水罐王 / 星空糖王 | 云白 / 天蓝 / 金黄 | 母体放大 + 内置王冠 | 288 |

两条实操补充：

1. **王冠画进图里，就别再用代码画一遍**。`drawEnemies` 里的 `drawCrown` 现在只在
   「图片没加载、退回几何绘制」的分支里调用——之前两顶冠叠在一起，肉眼一眼假。
2. **有的样本会自带一圈贴纸白边**（尤其云朵类），和其余素材的深褐描边对不上。
   `tangqiu-art.py` 里的 `strip_white_ring()` 把「已透明」与「近白」一起当可删区、从角点泛洪，
   背景和白边被整片吃掉，主体内部的白色高光因为被描边包围不连通，所以保留。

## 11. 三级降级

- **L1**：图片全部加载失败 → 回退 v0 几何绘制（`drawPlayerPath` / `drawEnemyPath` 保留）
- **L2**：部分失败 → 缺图的主体单独回退几何，其余用图
- **L3**：完全不可用 → 整局退回 v0，功能不受影响（冒烟测试覆盖两条路径）
