# 动作游戏动画层 · 组件规格

- 日期：2026-09-15
- 状态：**待评审**（依赖 [animation-pipeline-research.md](../research/animation-pipeline-research.md) §2 的技术结论）
- 定位：面向「2D 横版动作 / 对决」工具的**动画层**组件规格。这是路线 A（程序化骨骼/剪影）的落地规格。
- 与屏幕方向无关：本规格不预设横屏或竖屏，战斗空间几何由设计文档另定。
- 与题材无关，但**与骨骼拓扑有关**：本规格以**人形骨架**为示例，链式结构只用到其子集——见下方「适用范围」。

---

## 适用范围（先读这一节）

本规格写于题材确定之前，示例是人形动作角色。当前唯一消费方是 **舞火龙**——一条 **32 节链**，只用到本规格的一个**子集**。实现者不要照本规格去建 IK、朝向翻转与关键帧系统。

| 本规格章节 | 舞火龙（32 节链） |
|---|---|
| §1 双骨 IK | **不适用**（链不需要 IK） |
| §3 人形骨骼示例（髋/四肢）、`drawOrder` 的 `front`/`back` 双值 | **不适用**；改为等长链，绘制顺序按节索引即可 |
| §4 关键帧剪辑 | **不适用**；动作由**行波程序化生成**，无剪辑、无姿势混合 |
| §6 不变量 I1（枢轴）/ I2（父子相乘）/ I3（标量重建）/ I5（最短弧） | **适用** |
| §6 不变量 I4（姿势混合） | **部分**：角度最短弧适用；姿势混合不适用 |
| §6 不变量 I6（朝向翻转层序）、§7 | **不适用** |
| §8 次级运动 | **适用**（可用于龙尾余摆） |
| §9 动画事件（hit / cancel / recover） | **适用**（扫 / 缠 / 珠 的命中帧与收招窗） |
| §10 输入缓冲 / §11 性能 / §12 排除项 / §13 验收 | **适用** |

逐条不变量对照见 [wuhuolong-design.md](./2026-09-15-wuhuolong-design.md) §4.1 与 §4.7。

---

## 0. 为什么先定这一层

调研结论：路线 A 的**全部风险集中在六个已知的矩阵/插值陷阱**（[animation-pipeline-research.md](../research/animation-pipeline-research.md) §2.2）。这些陷阱的症状都是「看起来能动、但会缓慢漂移或过渡中缩一下」，**肉眼在短时间调试里很难发现**，正适合用无头断言锁死（本项目既有习惯）。

因此本层先于玩法定规格：它可测、可独立验证、且对形态（清关 / 对决）与题材都不敏感。

---

## 1. 边界

**做**：骨骼层级与变换、关键帧采样、双骨 IK、朝向翻转与层序、次级运动（弹簧/比例增益）、动画事件（命中帧 / 可取消窗）。

**不做**（YAGNI，明确排除）：
- 蒙皮网格与权重（分件刚体足够；蒙皮是路线 B 升级时才需要考虑的事）
- n 骨 FABRIK（双骨解析解覆盖四肢；除非出现长尾/多节鞭类需求）
- 运行时骨骼编辑器（编辑在构建期用数据文件完成）
- 物理引擎（次级运动用弹簧即可；`matter.min.js` 是 80 KB，本层不需要）

**依赖**：无。纯 ES2017 + Canvas 2D，走 `window` 命名空间，无构建链、无 WASM、无 Worker。

---

## 2. 模块接口

沿用仓库既有约定（经典脚本 + `window` 命名空间）：

```html
<script src="./assets/data.js"></script>      <!-- 静态数据（骨骼 + 关键帧） -->
<script src="./assets/anim.js"></script>      <!-- 本层 -->
<script src="./assets/combat.js"></script>    <!-- 战斗核心，消费动画事件 -->
<script src="./assets/main.js"></script>      <!-- 装配 + 触屏输入 -->
```

```js
window.XxxAnim = {
  build(manifest, parts),          // 建骨骼树；parts 为分件资源（Image 或矢量绘制函数）
  clip(name),                      // 切动画（带最短过渡时间）
  update(dt),                      // 固定步长推进；返回本帧触发的事件列表
  draw(ctx, camera),               // 绘制（含朝向翻转的层序）
  setFacing(sign),                 // +1 / -1
  boneWorld(id),                   // 只读世界矩阵，供战斗核心取命中点
  debugState()                     // 无头断言用：所有标量通道 + 世界矩阵
};
```

`update(dt)` 的 `dt` 由战斗核心的**固定步长累加器**驱动（沿用 `tools/houyi/assets/main.js` 的 `while (acc >= STEP && guard < 6)` 写法），本层不自持 `requestAnimationFrame`。

## 3. 骨骼数据格式（构建期产出，随包离线）

```js
// assets/data.js
window.XxxData.SKELETON = {
  parts: [
    // pivot 必须在「分件局部坐标」下 —— 见不变量 I1
    { id: 'hip',    parent: null,    pivot: [0, 0],    length: 0,   draw: 'hip' },
    { id: 'torso',  parent: 'hip',   pivot: [0, -6],   length: 46,  draw: 'torso' },
    { id: 'armL',   parent: 'torso', pivot: [-9, -38], length: 30,  draw: 'armUpperL' },
    { id: 'foreL',  parent: 'armL',  pivot: [0, 30],   length: 28,  draw: 'armLowerL' },
    { id: 'legR',   parent: 'hip',   pivot: [5, 6],    length: 34,  draw: 'legUpperR' }
    // ...
  ],
  // 每个分件两个层序值，按朝向选用 —— 见不变量 I6
  drawOrder: { 'armL': { front: 5, back: 1 }, 'torso': { front: 3, back: 3 } }
};
```

**髋为根**（与 Godot cutout 惯例一致）：便于整体位移/接地判定，且避免在根上引入额外旋转。

## 4. 动画数据格式

时间轴按「通道」组织，**状态只存标量，不存矩阵**（见不变量 I3）：

```js
window.XxxData.CLIPS = {
  'attack1': {
    fps: 24, loop: false,
    tracks: {
      'armR.angle':  [[0, -20], [4, -95, 'so'], [9, 40, 'si'], [14, -20]],
      'armR.x':      [[0, 0], [9, 6]],
      'hip.y':       [[0, 0], [4, -3], [9, 2], [14, 0]],
      'head.angle':  [[0, 0, 'sio'], [9, -8]]
    },
    events: [                                   // 战斗核心消费
      { frame: 9,  type: 'hit',     box: 'atk1' },
      { frame: 11, type: 'cancel',  into: ['attack2', 'dash'] },
      { frame: 14, type: 'recover' }
    ]
  }
};
```

- 缓动标识：`li`(线性) / `si`(sin-in) / `so`(sin-out) / `sio`(sin-in-out)，与调研参考实现同构，便于对照。
- 位置类通道使用**单调保持的三次插值**（Fritsch–Carlson）；**角度通道保留过冲**——过冲正是回弹感的来源，不加单调约束（见不变量 I4）。

---

## 5. 运行期更新顺序（不可交换）

```
每帧（固定步长）：
  1. 采样所有通道 → 得到本地 TRS 标量
  2. 解算双骨 IK（若有目标）
  3. 从根遍历一次，算世界矩阵  M_world = M_parent × M_local
  4. 绘制（按朝向选层序）
```

**顺序错的后果**：先蒙皮/绘制再用 IK = 用上一帧的矩阵；把 IK 算出的世界角度写回本地通道 = 父旋转被算两次。

## 6. 六个强制不变量（本层的验收核心）

每条都来自调研中的已知陷阱，且都可无头断言。

| # | 不变量 | 断言方式 | 违反症状 |
|---|---|---|---|
| **I1** | 枢轴在分件局部坐标；变换用 `T(p)·R(θ)·T(-p)` | 绕枢轴旋转后，枢轴自身的世界位置不变（容差 <0.01px） | 肢体绕画布左上角公转 |
| **I2** | 子骨用 `M_parent × M_local` | 仅平移根骨 (20,-10)，所有后代世界位移等于 (20,-10) | 子骨不跟随 |
| **I3** | 每帧从标量通道**重建**矩阵，绝不累乘 | 同一姿势连续求值 1 万帧，世界矩阵逐元素变化 <1e-6 | 角度缓慢漂移、缩放跑偏 |
| **I4** | 姿势混合在 TRS 通道级进行；角度走最短弧 | 两个差 90° 的姿势取中间权重，**矩阵行列式 = 1.0**（容差 1e-3） | 过渡中角色「缩一下」——朴素逐元素插值 `det = (1 + cosθ)/2`：45°→**0.854**、90°→**0.50**、180°→**0** |
| **I5** | 角度最短弧：`((t-s+180)%360)-180` | 350°→10° 的插值增量 >0 且 = +20° | 反向转 340° |
| **I6** | 绘制层序与骨骼树解耦，按朝向选值 | 翻转朝向前后，同一分件的层序值取到不同档；骨骼父子关系不变 | 转身后手臂穿帮 |

补充断言（回归用）：
- **骨长保持**：仅旋转+平移时，关节间距变化 <1e-6（暴露重复缩放）
- **单位姿势**：所有本地矩阵为单位阵时，每个顶点保持原坐标（暴露隐藏默认偏移）
- **行列式**：无缩放时旋转块行列式 ≈ 1

## 7. 朝向与层序

角色转向 = `scaleX = -1`（免费）+ **层序翻转**。层序与骨骼树必须解耦，因为转身时层序要整体翻转而父子关系不变。

每分件存两个层序值（`front` / `back`），绘制时按当前朝向选一个。朝向本身是独立状态字段，**不与骨骼角度耦合**——同一帧内「用于排序的朝向」与「用于缩放的朝向」必须一致，否则出现半帧穿帮。

---

## 8. 次级运动（头发 / 衣摆 / 灯穗）

二阶弹簧 + 比例增益，无需物理引擎：

```js
dest += (rest - dest) * springGain;
cur  += (dest - cur)  * propGain;
```

挂在骨链末端，输入为父骨的世界位移增量。**与确定性要求冲突**：弹簧参数必须固定、且不得依赖 `Math.random()`（仓库惯例：伪随机统一走 `mulberry32`）。

---

## 9. 与战斗核心的接口（动作游戏的关键耦合点）

命中判定**由动画事件驱动**，不是由计时器驱动：

```
anim.update(dt) → [{type:'hit', box:'atk1'}, {type:'cancel', into:[...]}] → combat 处理
```

- `box` 指向战斗核心的命中盒定义（hitbox 用 AABB；受击方 hurtbox 同样 AABB；同帧重叠即命中）
- **命中只结算一次**：每次 `hit` 事件带唯一 id，避免同一招式多帧重复扣血
- `cancel` 事件即**可取消窗**；触屏输入缓冲（见 §10）在此期间消费
- 受击方的反应是打击感的来源（调研 §1.3）：`hurt` / `launch` / `stagger` 三个受击动画必须存在且有夸张位移，否则「打上去像无效动作」

---

## 10. 与触屏输入的接口

本层不处理输入，但必须支持**输入缓冲**：战斗核心把「动画中按下的键」排入短缓冲队列（建议 6–10 帧），在 `cancel` / `recover` 事件到达时消费。这是触屏动作「不丢招」的关键（调研 §1.5 载荷性机制）。

判定窗需相对 60fps 放宽——触屏误差远大于键盘。

---

## 11. 性能预算（Canvas 2D）

- 2D 动作走 Canvas 2D，**不受** WebGL 的 DPR/纹理/draw call 分档约束
- 每帧零分配：世界矩阵用预分配的扁平数组复用，不在循环里建对象/数组
- 分件绘制用构建期预渲染的离屏 canvas（每个分件一次），运行时只做 `drawImage` + 变换
- 页面不可见时由战斗核心统一暂停（`visibilitychange`）

---

## 12. 明确不在本层做的事

不做蒙皮网格、不做 n 骨 FABRIK、不做运行时骨骼编辑器、不做物理引擎、不做 IK 拖拽调试 UI。这些在单角色 vertical slice 阶段都是纯增量成本，无助于验证玩法与手感。

---

## 13. 验收标准（取代肉眼验收）

1. §6 的 6 条强制不变量 + 3 条回归断言，全部写成 `tests/<tool>_anim_smoke.py` 的 Playwright 断言，零失败
2. `window.XxxAnim.debugState()` 可导出全部标量通道与世界矩阵，供断言直接比对
3. 同输入双跑逐帧一致（确定性；禁 `Math.random()`）
4. 集成后：`<tool>_smoke.py` 的连招状态机可达性断言通过（起手→命中→取消→收招闭环）
5. 未在真机验证的部分，交付说明标记「性能未实测」
