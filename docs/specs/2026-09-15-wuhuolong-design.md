## ⚠️ v2 重构决策（2026-09-16，取代 v1 形态）

**触发**：用户否决 v1 形态——「更类似跑酷了，实际上和 DNF 那种 2D 横版是不一样的」。核对代码后确认**不是观感问题，是结构问题**：

| v1 实现 | 位置 | 性质 |
|---|---|---|
| `S.x += SPEED * dt` | `game.js` | 前进位移自动，玩家无 x 轴主权 |
| 相机持续跟随龙头 | `scene.js` | 世界永远在滚 |
| `beatDist >= len` 过关 | `game.js` | 按距离过关，非按清场 |
| 敌人沿整拍 x 区间预撒 | `game.js` | 敌人从身边滚过 |

这是**自动跑酷 + 反应式躲闪**，与 DNF「有界房间内玩家拥有走位主权、清场才开门」正交。

### v2 形态（已与用户确认）

| 项 | v2 决策 | 依据 |
|---|---|---|
| **玩家身份** | **舞龙人**（持竿的人），不再「你=整条龙」 | DNF 形态要求小体量角色；32 节龙占屏 38%，会挤掉读空间/读敌人的余量 |
| **龙的角色** | **武器**：龙身自竿梢延出、跟随身后扫场。「转向即大范围甩尾」成为核心机制 | 链式行波是唯一不可替代的技术资产，改为武器后更能发挥 |
| **移动** | **纯左右 + 跳**（经典横版） | 触屏最省手指；纵轴是跳跃而非走位，与「缠柱」机制契合（柱挂走廊） |
| **房间** | 每拍 = 有界走廊房间；相机跟随玩家但**被房间边界夹住** | DNF 房间语义 |
| **过关** | **清场才开门**；走到门口进入下一间 | DNF 房间语义 |
| **输入** | 左 / 右 / 跳 / 竿刺（4 输入） | 替掉 v1 的 drag-y + 单击/双击/长按三手势 |

### 存活（不动，仍为本作技术资产）

- `chain.js` 全量：32 节骨骼链、行波、`MAXTURN` 几何约束、`wrap()` 缠缚、`shortest()` 角度环绕
- 香火粒子系统（`fire.js`）、`mulberry32` 确定性随机（`rng.js`）
- 夜间剪影 + 发光 + 皮影分件素材的美术方向
- 香火资源经济（DRAIN / 击杀回火 / DIM）与「香火即命」压力
- 敌人类型（疫气 / 瘟鬼）与 Boss 三阶段、三路净化、归天终章
- 四拍的文化命名与非遗准确性（开光 / 过桥 / 缠双柱 / 结团圆）

### 取代（重写）

- 自动前进、距离推进、无限滚动相机、沿路撒敌、drag-y 输入
- 龙作为「玩家本体」的渲染锚定 → 改为「竿梢锚定」

### 机制新增（v2 独有，来自「龙=武器」）

**转向即甩尾**：玩家反向移动时，37 世界单位的龙身必须在数帧内整体摆到另一侧——这不是补间动画，是 `chain.js` 的 `setHead` 位移上限逼出的**真实物理摆动**。它天然成为本作最强的清场手段，且**不需要额外按键**（触屏零成本）。

> 这条是本次重构的技术红利：v1 里它是「相机滚太快」的副作用，v2 里它变成核心玩法。

## 0. 产品定义

> ⚠️ 本节 v1 表述（「玩家不是武者，是一条龙」「操作只有拖动与一个按钮」）已被 §v2 取代，仅保留文化叙事部分。

一句话：**你是大坑的舞龙人，舞着一条插满香火的火龙，在夜间街巷里清到瘟神面前，然后送它归天。**

单局目标 **3–5 分钟**，四室 + 尾声完整闭环。零外部素材（全程序化），包体目标 **< 100 KB**（同系列零素材工具实测 12–24 KB）。

### 2.2 起源

光绪六年（**1880**），大坑爆发瘟疫。村中父老获菩萨报梦：**中秋前后舞火龙绕村巡游、燃放炮竹，可驱瘟疫**。村民依计而行，瘟疫果然消除，遂成年例。据传瘟疫前村中曾打死一条大蟒蛇、蛇尸翌日不翼而飞。

### 2.3 形制（可直接转成游戏参数）

| 项 | 值 |
|---|---|

| 全长 | **67 米**（约 220 尺；连龙头与龙头绳约 240 尺） |
| 香 | 插**逾万枝长寿香**（一说二万五千枝） |
| 扎作材料 | **珍珠草（米仔草）**——禾秆草、水草、杂草都不行：水草一干就缩，杂草会碎 |

| 龙珠 | 两颗 |
| 龙头工艺 | 火焙藤枝使其弯曲，加纸牙，插电筒作眼 |

### 2.4 仪式流程（本作的关卡结构来源）

1. 农历八月十四晚，于**莲花宫**为火龙**点睛、簪花、挂红**（开光）
2. 起龙后先在浣纱街向嘉宾**打龙饼（喜结龙团）**
3. 按传统游街：浣纱街、新村街、施弼街、京街、书馆街等
4. 表演程式三段：**火龙过桥** → **火龙缠双柱** → **彩灯火龙结团圆**
5. 每晚约十点半结束；八月十六最后一晚**逆时针**绕村一周（行大运）
6. 终章「**龙归天**」：火龙舞至铜锣湾避风塘，祭祀后送入海中

> **仪式的「表演程式三段」（过桥 → 缠双柱 → 结团圆）就是关卡的第 2–4 拍。** 前面加第 1 拍「开光」（点睛·簪花·挂红，兼教学），最后接尾声「龙归天」，正好构成完整闭环。这不是硬凑，是民俗自带的叙事结构。

### 2.5 社区与文化背景

- 19 世纪中叶大坑为著名**客家村**；仪式主持**须由客家人担任，禀神须用客家话**
- 舞火龙亦见于**薄扶林村**（2014 列入香港非遗清单，2017 列入香港非遗代表作名录）
- **大坑火龙文化馆**：书馆街 12 号，原址为 1909 年晚清「孔圣义学」，1949 年重建，2013 年纳入第四期活化历史建筑计划，2022-06-11 开幕
- 1942–1944 日占时期、2020–2022 疫情期间曾停办

## 3. 核心机制

### 3.1 玩家 = 整条火龙

龙头由输入驱动，**龙身 32 节自动跟随**。玩家不去「操控 32 个关节」，只控龙头——这是「舞龙」的真实逻辑，也是技术最简解。

### 3.2 操作：两拇指，但无摇杆

**本作不需要虚拟摇杆**——龙头直接跟随手指，省掉了一整类摇杆适配问题（死区、归一化、方向量化）。但仍需要**两个独立的手势空间**，否则手势互相冲突。

| 手 | 载体 | 手势 | 行为 |
|---|---|---|---|
| 左（或任意处） | 全屏拖动区 | 拖动 | 龙头跟随手指移动（带最大速度/角速度约束，龙身产生拖尾张力） |
| 右 | **一个「舞龙式」按钮** | 点按 | **扫**：甩尾横扫（近身范围，击退） |
| 右 | 同上 | 长按 | **缠**：缠柱（进入缠缚态，可用地形借力/换向） |
| 右 | 同上 | 双击 | **珠**：龙珠冲击（远程，消耗「香火」） |

**为什么必须拆两个空间**：若把移动与三种舞龙式都放在同一根手指上，「点按 vs 拖动的起始」「长按 vs 慢速拖动」「双击 vs 两次点按」三组都无法在按下瞬间判定；而且「长按蓄力」会锁死移动。拆开后，移动与动作在**不同 `pointerId`** 上，判定互不干扰——这正是 DNF 手游「左手移动 + 右手一键连招键」的结构（[touch-action-research.md](../research/touch-action-research.md) §1.1）。

**按钮内的三手势判定**（同一 `pointerId`，用时间阈值区分，全部为可调常量）：

```
pointerdown: 记 t0
pointerup:   dt = now - t0
   dt < TAP_MS(180)        → 待定：若 DOUBLE_MS(260) 内出现第二次 → 珠；否则 → 扫
   TAP_MS ≤ dt < HOLD_MAX  → 缠（进入缠缚态，可保持）
```

**必须避开的坑**：双击的第一击不能立即触发「扫」，否则每次双击都先扫一下。做法是 `TAP_MS` 内的点按先入**待定队列**，`DOUBLE_MS` 超时后才结算为「扫」。这是延迟换正确性的取舍，`TAP_MS` 需实机调参。

按钮位置、尺寸与触控热区（≥44px）在方向读数回来后按拇指舒适区定（见 §11）。

平台调研已验证「单指滑动」形态的可行性（《唯我独尊》竖屏单指模式），也验证了「一键多技能」按钮（DNF 一键连击键）。本作是两者组合，且**不占用摇杆区**。

`tools/yueyan/assets/scene.js` 里那套摇杆实现**本作不需要**——但它的两条血泪教训（`setPointerCapture` 必须 try/catch 容错；`pointermove` 绑 `window` 并门控 `pointerId`）在拖动与按钮上同样适用，直接沿用。

### 3.3 资源：香火

火龙插满长寿香——**香火即生命值与资源**。

- 香火随移动/受击**逐渐烧尽**（时间压力）
- 击溃邪祟可**回香**
- 「珠」消耗香火
- 香火低于阈值 → 龙身发暗、速度下降（**视觉与机制同源**：龙真的暗下去了）

这条把「民俗事实」直接变成机制，不需要额外解释成本。

### 3.4 敌人：瘟疫邪祟

主题上直接取自 1880 年瘟疫起源：疫气、瘟鬼。

- **疫气**：无实体，需用「扫」驱散，会附着龙身加快香火损耗
- **瘟鬼**：有实体，会扑咬龙身，需击退
- 差异靠**行为**而非贴图——契合「零资产 + 剪影」路线

### 3.5 Boss：瘟神

依 1880 瘟疫叙事立起的具象反派。三阶段递进（对应仪式三段）。

**关键设计：Boss 战不是「打到血条清零」，是「把火龙缠上它、以香火净化它」**——用「缠」把龙身缚住瘟神，香火持续灼烧直到净化完成。这样 1v1 的对抗性成立，但内核是**仪式**而非杀戮，与民俗原意一致。

### 3.6 终章：龙归天

净化后进入终章：火龙逆时针绕行一周，舞向避风塘，**送入海中**。

- 不是奖励结算页，是一段**不可操作的仪式演出**（可看、可截图）
- 分享卡在此时生成（见 §6.3）

## 4. 技术实现

### 4.1 链式骨骼 + 行波驱动

**不做人形骨骼那一套**：不需要双骨 IK、不需要蒙皮、不需要朝向层序翻转。对照 [action-anim-layer-spec.md](./2026-09-15-action-anim-layer-spec.md) §6 的六条不变量：

| 不变量 | 本作 |
|---|---|
| I1 枢轴在分件局部坐标 | **适用**（每节绕上一节末端旋转） |
| I2 `M_world = M_parent × M_local` | **适用**（核心） |
| I3 每帧从标量通道重建矩阵，不累乘 | **适用**（每节只存一个本地角度） |
| I4 姿势混合在 TRS 层 | **部分**：角度最短弧适用（I5 同理）；「姿势混合」不适用（本作无关键帧剪辑，动作为行波程序化生成） |
| I5 角度最短弧 | **适用** |
| I6 层序与骨骼树解耦、按朝向翻转 | **不适用**（无左右朝向）。但**链的绘制顺序仍需处理**——按节索引从尾到头绘制即可，属平凡问题，不是 I6 那类穿帮风险 |

```
龙头：位置由输入决定，朝向 = 移动方向
第 i 节（i = 1..32）：
    target = 朝向第 i-1 节（沿指向）
    angle  = 限制角速度后逼近 target
    angle += 行波：A * sin(2π * (t * freq - i * phase))   ← 相位随节索引延迟
```

**行波相位延迟**是龙「活」的关键——同一时刻沿龙身形成 S 形，而不是整条龙硬邦邦地转。

- **状态只存标量**（每节一个本地角度），每帧从标量重建变换——严格遵守不变量 I3
- 链长守恒：相邻节距离不得变化（不变量回归断言）

**已数值验证**（2026-09-15；32 节 / 行波 A=0.55、freq=2.2、k=0.55 / 每节转角上限 0.42 rad / 400 步 @60fps）：

| 指标 | 实测 | 判定 |
|---|---|---|
| 链长守恒（相邻节间距最大偏差） | **4.7e-15**（节长 L=2.0） | 严格守恒 ✓ |
| 蛇形（沿身转向角符号翻转次数） | **27** | 明确 S 形，非刚性直线 ✓ |
| 横向摆幅 / 全长 | **0.457** | 龙的体量比例合理 ✓ |
| 沿节索引转角序列 | 正负交替（+51° / −34° / +50° / −47° …） | 行波沿身传播成立 ✓ |

**结论：链式骨骼 + 行波架构成立**，且链长守恒可用断言锁死。注意这是**设计期量级验证，不是真机性能实测**。

### 4.2 香火粒子

- 沿链每节采样固定数量的发射点，按节索引错开相位
- 粒子：上浮为主 + 微风横向扰动 + 少量重力，寿命短（香火是**烧着的点**，不是烟花）
- **对象池**，预分配，运行期零分配
- 确定性：伪随机统一走 `mulberry32`，**禁 `Math.random()`**（仓库惯例，且保证逐帧可复现、可断言）

### 4.3 火焰发光（唯一的视觉风险点）

- 离屏预渲染**径向渐变发光 sprite**（构建期一次），运行期只做 `drawImage` + 变换合成
- 用 `globalCompositeOperation = 'lighter'` 叠加 → 香火密集处自然过曝成暖白光带
- **不做真实光照**、不做泛光后期、不做 shader（Canvas 2D 路线，不受 WebGL 分档约束，也不必处理 context lost）

> 与打铁花的本质区别：**火龙的香火点是沿龙身结构分布的**（每节插香），是有结构的火；打铁花是无定形飞溅。有结构 = 可控。

### 4.4 渲染

- Canvas 2D，分层：夜空渐变 → 远景街巷剪影 → 火龙（含发光）→ 前景雾/烟 → UI
- 摄像机跟随龙头横向平移（视差 2–3 层）
- 战斗空间几何（真横版 / 竖屏横条带）**见 §11 待确认**——本层按「逻辑坐标 + 摄像机」实现，与屏幕比例解耦，方向读数回来后只改取景参数，不动逻辑

### 4.5 音频（Web Audio 程序化，零文件）

舞龙由**锣鼓**驱动，这正好是可程序化的：

| 音 | 合成方式 |
|---|---|
| 鼓 | 低频正弦快速下滑 + 短噪声包络（约 60–120 Hz，衰减 <150 ms） |
| 锣 | 多个**失谐**振荡器叠加（非谐和音），长衰减 |
| 起龙/开光 | 锣 + 鼓组合，留白后重击 |
| 香火损耗告警 | 高频细碎噪声，随阈值变化频率 |

沿用仓库既有 `assets/audio.js` 形态（`createOscillator` + `createGain` + 指数包络），并提供 `unlock()` / `setMuted()`。

### 4.6 确定性

- 禁 `Math.random()`
- 逻辑跑**固定步长**（沿用 `tools/houyi/assets/main.js` 的 `while (acc >= STEP && guard < 6)` 写法），渲染插值
- 同种子双跑逐帧一致（可断言）

### 4.7 碰撞（「缠柱」的硬需求，不是免费的）

§3.2 的「缠」与 §5 第 3 拍「火龙缠双柱」都要求**龙身能缠住柱子**。这是本作唯一的非平凡碰撞需求，必须显式实现：

| 碰撞对 | 用途 | 做法 |
|---|---|---|
| 龙头 ↔ 地形边界 | 不越界 | AABB / 线段 |
| **龙身各节 ↔ 柱** | **缠柱** | 每个柱为一个圆（半径 r）；对每一节做「点到圆心距离 < r + 节半宽」检测；命中则该节**贴在圆柱面上**（沿径向投影），并记录缠缚节数 |
| 龙身 ↔ 敌人 | 「扫」的命中判定 | 节 ↔ 敌人 AABB 重叠；每次攻击只结算一次（攻击 id 去重） |
| 龙身 ↔ 龙身 | 自交 | **不做**（剪影龙自交视觉上可接受，做了成本高收益低） |

- 缠缚态：缠住 ≥N 节即进入缠缚态，可用于（a）借力急转（b）对 Boss 的净化
- 缠缚必须**可解除**，且解除后龙身不得残留形变（链长守恒断言覆盖）
- 碰撞检测按节做（32 次），单帧成本可忽略，无需空间划分

## 5. 关卡设计

**一段街巷，四拍推进**——直接映射仪式流程：

| 拍 | 名称 | 内容 | 对应仪式 |
|---|---|---|---|
| 1 | **开光** | 莲花宫起龙，教学：拖动 / 扫 / 缠 / 珠 | 点睛·簪花·挂红 |
| 2 | **火龙过桥** | 推进，桥面窄、两侧有缺口；疫气群 | 火龙过桥 |
| 3 | **火龙缠双柱** | 双柱地形；用「缠」借力换向，同时被瘟鬼围攻 | 火龙缠双柱 |
| 4 | **彩灯火龙结团圆** | Boss：瘟神，三阶段（缠缚 → 香火灼烧 → 净化） | 彩灯火龙结团圆 |
| 尾声 | **龙归天** | 不可操作的仪式演出 + 分享卡 | 龙归天 |

- 无多关卡、无地形随机、无道具系统（**v1 明确不做**，见 §10）
- 难度曲线：第 2 拍教机制、第 3 拍组合机制、第 4 拍考验机制
- 全流程 3–5 分钟，可重玩（重玩动机 = 香火剩余量 / 净化速度 → 可晒的成绩）

## 6. 视觉与素材

### 6.1 视觉语言（从题材生长，零外部素材）

| 元素 | 做法 |
|---|---|
| 火龙 | 程序化矢量：32 节点连成**发光曲线**，龙身由香火点群构成，龙头用少量固定形状（角/须/牙） |
| 香火 | 发光 sprite 粒子，暖橙→金白 |
| 夜空 | 径向渐变 + 少量星点（`mulberry32`） |
| 街巷 | 多层剪影楼宇（唐楼轮廓 + 骑楼 + 招牌），全黑剪影 + 少量暖黄窗光 |
| 雾/烟 | 半透明剪影层缓慢平移 |
| 色彩 | 夜色冷（深青/靛）对撞香火暖（橙/金）——**唯一强调色就是火光**，符合「一屏一主角」 |

### 6.2 动效准则（沿用 `docs/research/design-knowledge.md`）

- 落定必呼吸：开光仪式、龙归天各留 ≥1s 静止
- 速度感来自加速度：龙身行波非线性、冲击有 riser→impact
- 一屏一主角：火龙永远是唯一主角，街巷剪影只做衬托
- 结尾即峰值：龙归天是全片能量最高点

### 6.3 分享卡（成品出口）

- 时机：龙归天结束
- 内容：火龙入海画面 + 一行成绩（剩余香火 / 净化耗时）+ 非遗信息（「中秋节（大坑舞火龙）· 国家级非遗 Ⅹ-5」）
- 链路：canvas → `toDataURL` → `writeTempFile` → `saveImageToPhotosAlbum` / `postNote`，`window.xhs?.miniTool` 判空降级为提示
- 可晒性：调研指出晒单需要「可命名的成就单元」→ 卡面给出可命名的成绩（如「满香归天」「八息净化」）

## 8. 有意识的决策

| 决策 | 理由 | 代价 |
|---|---|---|
| **玩家 = 整条龙，而非武者** | 免去人形骨骼全部复杂度；且「舞龙」的真实逻辑就是一条活龙 | 失去「角色」人格化，靠龙头神态与行波补 |
| **单指拖动，不做虚拟摇杆** | 平台已验证单指形态；去掉一整类触屏适配问题；不占左下拇指区 | 操作深度上限较低，靠「扫/缠/珠」三式补 |
| **香火即血量** | 民俗事实 → 机制，零解释成本；视觉与机制同源 | 需要精细的损耗调参 |
| **Boss 是净化而非击杀** | 与民俗原意一致；差异化于所有「打血条」动作游戏 | 需要把「缠缚→灼烧→净化」的反馈做得足够清楚 |
| **终章不可操作** | 仪式需要庄重；也降低收尾的实现风险 | 少一段互动 |
| **全程序化零素材** | 规避打铁花的资产管线风险；包体 < 100 KB | 视觉上限受限，靠剪影+发光取胜 |
| **v1 不做多关卡/道具/成长** | 22 天窗口下，先要一个完整闭环而非内容量 | 可重玩性靠成绩而非内容 |

## 9. 验收标准

### 9.1 功能

- 四拍 + 尾声完整闭环，可从开光走到龙归天
- 三种舞龙式（扫/缠/珠）均可触发且反馈清晰
- 香火损耗 / 回复 / 枯竭状态机正确
- Boss 三阶段可达成，净化判定准确
- 分享卡可生成并走通端能力链路（含无端能力降级）

### 9.2 无头断言（`tests/wuhuolong_smoke.py`）

- 链长守恒：任意时刻 32 节相邻间距恒定（容差）
- 状态仅标量：连续求值 1 万帧，变换无漂移（不变量 I3）
- 行波相位：同一时刻沿链的角度序列呈预期相位差
- 确定性：同种子双跑逐帧一致；`assets/*.js` 零 `Math.random()`
- 状态机可达：开光 → 过桥 → 缠柱 → 团圆 → 归天 全部可到达
- 零 console / pageerror

### 9.3 规范门禁（.skill 1.6.0）

- `index.html` 在 zip 根；无内联脚本 / 行内事件 / `eval` / `type="module"`
- 经典脚本 + `window` 命名空间；ES2017 以内
- Chrome 61 CSS 基线（无 `inset` / `clamp` / flex `gap` 无回退 / `aspect-ratio` / `dvh`）
- 包体 < 100 KB（上限 10 MiB，建议 2 MiB）
- 无外部引用、无 Base64 超 1 MiB

### 9.4 视觉

- **第 4 天视觉门**（见 §10）通过
- 夜景剪影 + 香火发光在 390 宽下有足够对比度与辨识度
- 龙身在运动中最窄处不糊成一条线

### 9.5 明确不验收的项

- 真机帧率、真机手感、真机触感反馈——**未实测**，交付说明如实标注（`navigator.vibrate` 在 iOS 引擎下已确认不可用，不作为反馈通道）

## 10. 实施顺序（7 天建造 + 审核缓冲）

| 天 | 任务 | 产出 |
|---|---|---|
| **D1–D3** | **只做火龙本身**：链式骨骼 + 行波 + 香火粒子 + 夜景剪影 + 摄像机 | 可动的火龙（无玩法） |
| **D4** | **视觉门** — 出截图做验收 | 过门 → 继续；**不过门 → 立即降级**（回到纯剪影 / 缩到「龙归天」单场景仪式），不硬撑 |
| D5 | 横版推进 + 疫气/瘟鬼 + 香火机制 | 可玩的推进段 |
| D6 | Boss 三阶段 + 龙归天 | 完整闭环 |
| D7 | 触屏三式 + 分享卡 + 锣鼓音频 + 包体/规范门禁 + 无头断言 | 可交付 zip |
| D8–D10 | **审核缓冲**（调研记录过审核会被拒且无原因，预留 2–3 天返工） | 过审 |

**为什么先做火龙**：打铁花的教训是「视觉不达标」，但它是做到 v6 才发现。把最高风险项前置 + 设一个明确的过门标准，最坏情况只损失 4 天。

### 10.1 工期风险（必须正视，此前我没有交代）

上表的「7 天建造」是**按本系列既有速度外推的估计，未经验证**。外推依据与反证：

| 参照 | 事实 | 可比性 |
|---|---|---|
| 全系列速度 | 8/12–9/14 共 **18 个工具 / 约 34 天** | 那是**较简单交互**的均值（剪纸、占卜、合成、换装、拾色） |
| `shanhai`（纵版 STG） | 811 行 / 约 1–2 天 | 动作类，但系统数远少于本作 |
| `longzhou`（跑酷） | 24 KB / 约 1–2 天 | 同上 |

而舞火龙需要落地的系统清单是：

> 链式骨骼 + 行波 / 香火粒子 / 夜景剪影 + 摄像机 / 横向推进 + 两类敌人 / Boss 三阶段 / 龙归天演出 / 触屏三式（含双击消歧） / 分享卡端能力链路 / 锣鼓程序化音频 / 包体与 1.6.0 规范门禁 / 无头断言套件

**结论：这是本系列系统数最多的一个工具，7 天属于乐观估计。** 因此：

**D4 视觉门必须同时当工期门用**——

| D4 情形 | 处置 |
|---|---|
| 过门且 D1–D3 按期 | 按原计划推进 |
| 过门但 D1–D3 超期 | **立刻砍内容**（Boss 降两阶段 / 推进段减半 / 分享卡简化），**不允许挤压 D5–D7** |
| 不过门 | 走降级路径（纯剪影 / 缩到「龙归天」单场景仪式） |

**那么 9/25 到底是硬承诺还是「赶上最好」？** 这直接决定边界取舍：

- **硬承诺** → 建议 §11 第 2 项再收一档（例如去掉「火龙缠双柱」整拍、去掉两类敌人只留一类），用确定性换掉一个 beat
- **赶上最好** → 按现计划走，滑到 10/1 反而不亏（国庆流量块比中秋更大，且是完整 7 天黄金周）

2. **缩规模边界** —— **已按头部窗口决策定为：v1 不做多关卡 / 多 Boss / 道具成长，只做「一条街巷 + 一个 Boss」。** 该边界是按「**9/25 赶上最好、10/1 为硬死线**」这一窗口推算的 7 天建造期（不确定性见 §10.1）。三种可能的调整，对应不同取舍：

   | 你的取向 | 边界调整 | 死线 |
   |---|---|---|
   | 认可以上（默认） | 不变 | 9/25 尽力，10/1 兜底 |
   | 更看重内容量 | 放大（多关卡 / 多 Boss / 道具成长） | 放弃 9/25，以 10/1 为唯一目标，建造约 14 天 |
   | **9/25 是硬承诺**（与窗口决策不同） | **再收一档**：去掉「火龙缠双柱」整拍 / 两类敌人只留一类 | 9/25，用确定性换掉一个 beat |
3. **净化反馈的可读性**是最大设计风险（非技术风险）：玩家能否一眼看懂「缠住 → 灼烧 → 净化」的进度。D6 需专门验证，必要时加 UI 指示。
