## 1. 定位

把打铁花做成一座**可以逛的数字展览**：一屏一个流派、一种打法、一个知识点。视觉质量由插画素材承担，代码负责动效编排、粒子与转场——这是前四版失败教训的直接结论（代码不画画面）。

核心体验公式：**一屏 = 一张插画 + 一个主角 + 一个签名交互 + 一张展签**。

## 3. 五屏结构与动效配方卡

> 每张配方卡 = 阶段（蓄力→冲击→落定→呼吸）+ 时值 + 缓动。全部非线性（准则 2），节奏宁慢勿快（准则 3），落定必呼吸（准则 1）。时值为首版基准，验收时按「放慢一档」原则校准。

### 屏 1 · 序「点炉」

- **插画**：焦墨夜空，地平线一点炉火，远处艺人剪影；上部留空给标题
- **主角**：炉火（唯一光源，准则 5 单主角）
- **签名交互**：**长按**任意处 → 炉火渐亮，金粉余烬加速上升；满后进入下一屏
- **配方卡**：
  - 标题入场：竖排「打铁花」逐字浮现，每字间隔 0.8s，easeOutCubic，落定后 hold 1.2s（准则 1）；整条开场弧 ≥3s（准则 3）
  - 长按点炉：热度非线性上升（easeInQuad，前慢后快），余烬粒子随热度加速（准则 2）
  - 点满：炉火一亮（easeOutExpo 0.4s）→ 呼吸 0.6s → 墨晕转场
- **展签**：打铁花｜民俗·国家级非遗｜北宋—明清｜「一勺铁水，打出满天金花」

### 屏 2 · 确山「打花棚」

- **插画**：高花棚剪影，棚上柳枝，棚下人群；暗底
- **主角**：花棚
- **签名交互**：**点按** = 挥棒击打 → 铁汁射向柳枝 → 棚上鞭炮连锁点燃
- **配方卡**：
  - 挥棒：0.12s easeInQuad 蓄力加速 → 击打瞬间铁汁迸发（easeOutExpo）
  - 鞭炮连锁：错峰点燃，间隔 0.08s 逐渐加速（准则 2 加速度+错峰），全亮后静止 0.5s（准则 2 收尾停顿）
  - 每屏 3 击点亮全棚，能量递进
- **展签**：确山打铁花｜河南确山｜2008 国家级｜「花棚柳枝，铁汁击棚，鞭炮齐鸣」

### 屏 3 · 暖泉「打树花」

- **插画**：古城墙夜景，墙面大片留暗（铁花绽放位）
- **主角**：城墙
- **签名交互**：**滑动** = 泼洒铁水 → 城墙上绽开树冠形铁花
- **配方卡**：
  - 泼洒：手势 1:1 跟随，铁水弧线 0.4s easeOutCubic
  - 绽放：树冠形分枝粒子 easeOutExpo，由触点向外生长
  - 落定呼吸 0.8s
  - 「富人放烟花，穷人打树花」作纹理态小字浮现（准则 7：不当主信息读）
- **展签**：暖泉打树花｜河北蔚县｜五百余年｜「铁水泼墙，树冠开花」

### 屏 4 · 泽州「打向天空」

- **插画**：旷野墨空，地平线炉火，上方大片留空（冲天铁花位）
- **主角**：冲天铁花
- **签名交互**：**点按** = 挥板 → 铁花冲天十几米
- **配方卡**：
  - 挥板 0.1s easeInQuad → 冲击 → 铁花冲天 easeOutExpo，金粉拖尾
  - 飘落 1.5s → 呼吸
  - 本屏粒子规模为前四屏之最（能量预峰值）
- **展签**：泽州打铁花｜山西晋城｜随明清冶铁而兴｜「操板击打，铁花冲天」

### 屏 5 · 尾「匠人」

- **插画**：匠人手部/侧影特写，暗调
- **主角**：手（旧疤新泡）
- **签名交互**：**点按** → 展签浮现 + 落款收尾
- **配方卡**（终章 = 全片能量峰值，准则 6）：
  - 金粉铁花雨全屏洒落（峰值特效，初版默认加码一档）
  - 竖排「匠人把危险留给自己，把美丽献给人间」逐字浮现，落定 hold 1.5s（准则 1）
  - 展签自下而上 easeOutExpo，落定 hold 1s
  - 落款：「非遗手作坊 · 打铁花」+ 双非遗注
- **展签**：总结签 + 打铁花×皮影戏双非遗注脚

## 4. 导航与转场

- **翻页**：竖屏整屏上滑（下一屏）/下滑（上一屏），可点右侧箭头；惯性滚动 + 吸附
- **进度**：右侧细线 5 段，当前屏金色（唯一强调色）
- **转场**：墨晕渲染（Canvas 2D 圆形墨扩散，easeInOutCubic 0.7s）；二期升级 WebGL 墨晕 shader
- 一屏只讲一个动效（准则 13），转场不抢戏

## 5. 工程方案

### 结构
```
tools/datiehua/
├── index.html
└── assets/
    ├── style.css        # tokens + 排版 + 展签
    ├── main.js          # 展册状态机 + 导航 + 交互路由
    ├── ink.js           # 墨晕转场 + 占位水墨背景渲染
    ├── particles.js     # 金粉粒子（mulberry32 种子随机，准则 10）
    ├── screens.js       # 5 屏配方卡实现
    └── img/             # 插画素材（占位先行，同名替换）
```

### 占位先行
先用程序化水墨占位背景（墨晕渐变 + 宣纸噪点）跑通全部逻辑与动效，插画到位后替换 `img/` 同名文件，零代码改动。

### 确定性（准则 10）
粒子全部 mulberry32 种子随机（seed 从屏号+击打序号派生），逐帧可复现、可断言。禁 Math.random()。

### 验证（准则 8/9：不把首检交给用户）
无头浏览器关键帧截图 + 像素断言：
- 标题落定帧（hold 期间）
- 各屏冲击瞬间（粒子爆发）
- 终章峰值帧（金粉雨密度）
- 展签可读性（字高 ≥ 帧高 5%，准则 7）

## 7. 二期升级项（本期不做）

- WebGL 墨晕转场 shader（canvas-ui Clouds/Liquid 技法自实现）

## 8. 验收标准

- [ ] 5 屏全通，签名交互互不相同（准则 9）
- [ ] 每屏单主角，无装饰性动画（准则 5/13）
- [ ] 所有运动非线性，关键落定有呼吸（准则 1/2/3）
- [ ] 金粉为唯一强调色，无其他彩色（准则 4/11）
- [ ] 粒子种子随机可复现（准则 10）
- [ ] 展签字高达标，文字两态清晰（准则 7）
- [ ] 终章为能量峰值（准则 6）
- [ ] 关键帧像素断言全过（准则 8）
- [ ] 通过 `.skill` 容器自检清单，zip < 2MB
