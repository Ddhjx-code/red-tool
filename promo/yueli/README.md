小工具 `tools/yueli` 的发布物料。**成品在图里，脚本能重出一遍。**

| 路径 | 内容 | 要不要发 |
| --- | --- | --- |
| `images/01.png` ~ `06.png` | 图文笔记六张，1080×1440（3:4） | 按序号发 |
| `video/yueli-17s.mp4` | 视频笔记，1080×1920，25fps，17s，无音轨 | 发，音乐在站内选 |
| `notes/xiaohongshu.md` | 两篇笔记的标题、正文、话题、发布顺序 | 照抄 |

`build/` 里的 `shots/`（界面截图）和 `cards/`（宣传图）是 `src/render.sh`、`src/shoot.sh`
的输出，随时可以重出，不入库。**要改图就改 `src/cards/p*.html` 再跑一遍，不要直接改 PNG。**

## 重新生成

依赖：Google Chrome（无头）、ffmpeg、python3。全部在 macOS 上跑通。

```sh
cd promo/yueli/src

./shoot.sh              # 生成预览壳 → build/shots/*@2x.png（4 张 780×1688）
./render.sh             # 六张卡 → build/cards/p1..p6.png（1080×1440）
./render.sh p3          # 只重渲一张

cd video
python3 render_frames.py    # 426 帧 → build/frames/，5 并发约 8 分钟
python3 render_range.py 265 319   # 改转场后只重渲这一段
./compose.sh                # → build/yueli-17s.mp4
```

出图后对比 `images/` 里已发布的那版，确认改动是想要的，再覆盖过去。

## 几个必须知道的坑

- **预览壳不是手写的。** `make-preview.py` 从 `tools/yueli/index.html` 现场生成：
  把资源路径改成绝对路径、注入模拟存储。工具改结构后不用同步任何东西。
  但入口脚本标签变了（`<script src=... date.js>`）会报错，那是提醒你模板变了。
- **无头 Chrome 会把窗口宽度钳到 500px。** 想要 390 宽的手机界面，必须用 iframe 固定
  390×844 再 2x 采样，直接 `--window-size=390,844` 会拍出假溢出。
- **`--virtual-time-budget` 至少 4000。** 弹层是在 `setTimeout` 里点开的，预算不够会
  拍到面板没弹出来的那一帧。弹层还要把过渡强制结束，否则拍到半截。
- **帧缓存会骗人。** `render_frames.py` 遇到已存在的帧就跳过，改了时间轴却不删旧帧，
  会得到「看起来渲完了其实没变」的结果。重渲区间用 `render_range.py`，它是覆盖。
- **转场要分层。** 遮罩和内容共用一个 opacity，中间态会出现半透明手机叠半透明文字，
  修法是拆成 `.pv-bg`（遮罩）和 `.inner`（内容）各自独立的时序。
- **视频不做交互录制。** 用负 `animation-delay` + `animation-play-state: paused` 把
  CSS 动画冻在任意时刻，逐帧截图再合成。录屏会掉帧，这样不会。

## 不做的三件事

不估算排卵期和易孕期；不出现疗效、备孕成功率之类说法；不做分享卡。
六张图和视频尾屏都带免责说明——这是这个品类最容易被限流的地方。
